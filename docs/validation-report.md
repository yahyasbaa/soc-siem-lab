# Validation report

Results of the final quality gate, run on 2026-10-03 on a single host (x86_64, 8 vCPU, 15 GB RAM,
Docker 29.3.1, Compose v5.1.1). Everything below was executed. Nothing is estimated.

## Procedure

1. `make distclean`: removed `.env`, certificates, generated config, venv, all Docker volumes, runtime
   logs and reports.
2. `make all`: setup (new secrets and certificates) → validate → up → health → inject all synthetic
   scenarios → detection tests → integration tests → report.
3. `make restart`: full `docker compose down` / `up`, dashboards re-imported, then the health check.
4. `make test`: the complete suite again on the restarted stack.
5. After removing the unused `<cluster>` block from `ossec.conf`: `make reload-rules` (health check) plus
   the infrastructure and SIEM-service tests.

### Detection coverage verified end to end (agent → manager → indexer)

* **36 detection rules** (+2 pipeline-heartbeat rules), each with at least one positive scenario.
* **38 positive expectations** across 31 positive scenarios. For each one the test checked rule id,
  level/severity, MITRE ids with technique/tactic enrichment, agent, location, decoder and decoded fields.
* **11 benign scenarios** with no false positives. In each case the benign events were confirmed ingested
  and the forbidden rules confirmed absent.
* **24 scenarios** additionally verified through `wazuh-logtest` (engine level, isolated sessions).

### Detection latency (event written on the lab host → alert generated by the manager)

| Run | Min | Avg | Max |
|---|---|---|---|
| Fresh install | 0.0 s | 0.31 s | 1.02 s |
| After full restart | 0.36 s | 0.89 s | 1.29 s |

The first alert became searchable in the indexer about 12 s after injection, mostly because of Filebeat
batching and the index refresh interval. Per-rule latency is in `docs/detection-catalog.md`.

### Negative checks (the tests fail when they should)

* **Rule removed.** Rule 100173 was deleted from the running manager only. The logtest test, the end-to-end
  test and the rules-loaded test for it all failed ("expected alert 100173 not found … the detection is
  broken"). The rule was then restored.
* **Agent stopped.** With `lab-nids-01` stopped, `health-check.sh` exited 1 with three failures (container,
  agent, heartbeat).

## Issues found and fixed during validation

| Issue | Fix |
|---|---|
| Correlation rules occasionally missed (events matched out of order by multi-threaded remoted/analysisd) | single worker settings via `20-deterministic-analysisd.sh` |
| Manager failed after an in-place container restart (stale PIDs, first-boot data copy) | `00-restart-safety.sh` |
| Rule edits not picked up (single-file bind mounts pin the old inode) | directory mounts |
| Windows XML rejected by the EventChannel decoder (double-quoted attributes) | single-quoted attributes, as Windows renders them |
| Certificate generator had no network (`network_mode: none`) | removed; setup needs Internet once |
| Health check read the archives too early on a fresh install | archives included in the wait loop |
| Dashboard index pattern lacked dynamic Suricata fields on a fresh install | `soc-lab-fields` index template + put-mapping before import |
